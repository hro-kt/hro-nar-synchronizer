# hro-nar-synchronizer

地方競馬(NAR)の単勝・複勝オッズを時系列で記録する。

## なぜ中央と別のリポジトリなのか

データ源も執行先も中央と共通点が無い。JV-Link は地方を配信せず(検証:
`hro-db/tools/nar_coverage.sql`)、IPAT は地方を扱わない。中央のコードに
「地方のための if」を足すと、開催日に動いているものを壊す。物理的に分ける。

あわせて、地方と中央を**混ぜない**ための防壁でもある。過去に地方/海外の
混入で検証を丸ごと汚染している。テーブルも `nar_*` で分ける。

## 中央と違う点(実測 2026-10-15)

| | 中央 | 地方 |
|---|---|---|
| データ源 | JV-Link (32bit COM) | netkeiba の HTTP のみ |
| ブラウザ | Playwright 必須 | **不要**(オッズ表はサーバ描画済み) |
| ログイン | プレミアム必須 | 単勝は非会員でも同値(締切直前は未確認) |
| 更新間隔 | 秒単位 | 中央値 31 秒 |
| 締切 | 発走時刻 | 発走2分前(SPAT4 の南関東のみ1分前) |

## 使い方

```bash
poetry install
hro-nar-synchronizer sync-races --date 20261016   # 開催一覧を取る
hro-nar-synchronizer collect --date 20261016      # オッズを記録し続ける
```

## 注意

- **`Waku*` は枠番、`W31` が馬番**。取り違えると別の馬にオッズが付く
- ページは **UTF-8**(meta に charset の記載が無い)
- 締切後のオッズは確定オッズ。判断に使うと未来を見たことになる
